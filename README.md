# 文档压缩标准化与打印排版工具

把 AI 对话里复制的作业/知识文本一键整理成排版紧凑、适合打印的 Word 文档。

> **只想用，不想装环境？** 下载仓库里的 [`文档压缩标准化工具.html`](./文档压缩标准化工具.html)，双击打开即可。单文件、离线、无需 Node.js。

- 纯浏览器离线运行，无需 API Key、无需联网
- **公式转 Word 原生公式（OMML）、化学式转真实上下标**
- 题目三级分级：■ 大题 / ◆ 小题 / ▸ 小问，选项自动弱化
- 清除 AI 客套话、压缩空行、过滤乱码、Markdown 表格与列表转 Word 原生格式
- **空白压缩：超长空格压成 1 格，大段空行换成一行分隔标号**
- **截图裁切排版：批量剔除状态栏/黑边/悬浮按钮，导出 A4 图片、ZIP 或 PDF**
- 支持批量处理多个 TXT/MD 文件并批量导出 .docx

## 粘贴转换：公式与化学式

粘贴 AI 回复后，工具会自动识别其中的公式与化学式，导出 Word 时输出为**可编辑**的格式。

### 支持的输入

| 类型 | 写法示例 |
| --- | --- |
| 行内/块级 LaTeX | `$x^2+y^2=r^2$`、`$$...$$`、`\(...\)`、`\[...\]` |
| 公式命令 | `\frac`、`\sqrt[n]{}`、`\sum`、`\prod`、`\int`、`\left( \right)`、`\lim`、`\sin \cos \log`、`\text{}`、`\mathrm{}`、`\mathbf{}`、`\mathbb{}`、希腊字母、关系符与箭头、上下标 |
| mhchem 化学 | `\ce{H2SO4}`、`\ce{Fe^3+}`、`\ce{2H2 + O2 -> 2H2O}`、`\pu{...}` |
| 纯文本化学式 | `H2SO4`、`Ca(OH)2`、`CuSO4·5H2O`、`NH4+`、`SO42-`、`Cr2O72-`、`CH3COOH` |
| 零散 LaTeX | `\alpha`、`x^2`、`\frac{a}{b}`（转为 Unicode 字符） |

### 输出的可编辑形式

- 数学公式 → **Word 原生公式对象（OMML `<m:oMath>`）**：双击就能编辑，Word 公式工具、字号、编号全部可用
- 化学式 / 离子 → **Word 真实上下标**：普通文字 + 上标/下标格式，改动不丢格式
- 化学方程式箭头（→ ⇌）、结晶水点号、状态 `(aq)` 按文字输出
- 页面预览只是近似示意，最终以导出的 .docx 为准

### 无法自动识别的情况（边界）

- 没有定界符（`$`、`\ce{}`）且结构复杂的长公式：只会做符号替换，不生成公式对象
- 多行环境：`align`、`gather`、`cases`、`matrix`、`\newcommand` 自定义宏
- `\overbrace`、`\underbrace`、`\boxed`、`\cancel` 等装饰命令
- 歧义缩写：`CO`、`COVID19`、`MP3`、`USB3` 等可能漏判或误判（已用「元素合法性 + 常见元素」双重校验降低误判）
- 结构式、键线式、SMILES、苯环、同位素组合
- 箭头上的反应条件（温度/催化剂）会被忽略，只保留箭头
- 中英文与公式之间没有空格时可能粘连
- 上下标嵌套超过两层、极复杂分式会降级显示

## 题目分级：■ 大题 / ◆ 小题 / ▸ 小问

AI 输出的作业文本层级是“平”的：`一、选择题` 和 `1. 下列…` 长得一样重，混在一起看不出结构。
打开「题目分级 ■ ◆ ▸」开关（默认开启）后按下表识别并替换符号。

### 识别依据（三条证据 + 反例防护）

| 证据 | 说明 |
| --- | --- |
| **序号字符集** | 中文数字（一、二、三）→ 大题；阿拉伯数字（1. 2. 3.）→ 小题；（1）（2）/ 1) → 小问；①②③ 本身已是符号，不再加标 |
| **递增序列** | 只有「上一个大题序号 +1」或全文首个「一、」才升级为大题；序号断裂就不升级——这是区分「一、二、三」式选项的关键 |
| **题干关键词** | 选择题 / 填空 / 判断 / 解答 / 计算 / 证明 / 阅读 / 作文 … 出现即认作大题，兼容分 Ⅰ、Ⅱ 卷后重新从「一、」开始 |

**反例防护**

- 连续 ≥3 行「中文数字 + 短内容（≤12 字）」→ 判为选项组，绝不加 ■
- `3.14 是圆周率` 这类小数不当题号（“.” 后紧跟数字即跳过）
- `$$ … $$` 公式块、``` 代码块内部的行完全不动

### 符号与层级

| 层级 | 符号 | 示例 | 导出的 Word 样式 |
| --- | --- | --- | --- |
| 大题 | **■** | ■ 一、选择题（每题3分） | 字号 +1pt、加粗、段前 10pt |
| 小题 | **◆** | ◆ 1. 下列各题… | 加粗、段前 6pt |
| 小问 | **▸** | ▸（1）求… | 不加粗、左缩进 0.25 英寸 |
| 选项 A/B/C/D | 无 | A. 蔗糖 | 左缩进 0.33 英寸、常规字重 |
| 选项 一、二、三 式 | **◇** | ◇ 一、北京 | 同上 |

- 原有题号文字（数字、括号形态）一律保留，只在前面补符号，不改内容
- 「一、二、三」式选项形态与大题完全一致，所以单独给 ◇，否则读者无法分辨
- 关掉开关即恢复原文，不做任何改动

### 边界

- 只有两项的中文数字选项组（不足 3 行）不加 ◇，可能仍显平淡
- 有序列表 `1. 2. 3.` 在作业场景下与“小题”等价，一律标 ◆；纯要点罗列也会被这样处理
- 完全靠缩进、无序号排版的题目无法识别（宁可不动，也不误加符号）

## Markdown 表格与列表

- `| 物质 | 质量 |` + `| --- | :---: |` 分隔行 → 生成 **Word 原生表格**：可编辑单元格、表头跨页自动重复、支持左/中/右对齐
- `- ` / `* ` / `+ ` 开头 → Word 项目符号列表（不再是纯文本的短横线）
- 表格单元格里的公式、化学式照常转成原生对象
- 不支持：合并单元格、单元格内换行（Markdown 本身也不表达这些）

## 空白压缩与分隔标号

粘贴来的文本常带着大量「看不见的版面杀手」：句中的超长空格、制表符对齐、整段空行。
打开「空白压缩 + 分隔标号」开关（默认开启，位于「精细处理选项」或「设置 → 处理工作流」）后按下列规则处理，**不新增、不删除任何可见文字**。

### 触发方式

- 独立开关，可与其它步骤任意组合；关闭时原文空白一个字符都不动（方便对照原稿）
- 实时预览与导出 Word 使用同一套规则，所见即所得
- 在流水线中位于「题号标准化」之后、「公式定界符规范化」之前

### 处理规则（阈值）

| 情况 | 规则 |
| --- | --- |
| 行内连续空白 **≥3** 个（半角空格、制表符、全角空格、NBSP） | 压缩为 1 个半角空格 |
| 行内连续 **≤2** 个空白 | 视为有意留白（中英文间距、手工对齐），原样保留 |
| 行尾空白 | 全部删除 |
| 行首缩进宽度 **≤4**（4 个半角 / 2 个全角空格） | 保留，护住段首缩进与嵌套列表 |
| 行首缩进宽度 **>4** | 视为粘贴垃圾，压成 2 个半角空格 |
| 连续空行 **≥3** 个 | 视为「分隔作用的大段空白」→ 换成一行 `──── ◆ ────` |
| 连续空行 **1~2** 个 | 正常段落间隔，保留，不插图符（避免整篇花掉） |
| 文首 / 文尾空白 | 直接丢弃 |
| 零宽字符（U+200B~U+200D、U+FEFF、U+2060） | 删除 |
| 制表符 | 按 4 个空格宽度折算 |
| **保护区域**：`$$…$$` 块级公式（可跨行）、``` 代码围栏内部 | 完全不压缩，避免破坏语法 |

### 压缩与分隔标号的取舍逻辑

- **能省成一行就省成一行**：3 个以上空行（约浪费 1/4 页）换成一行灰色居中细线，比空行紧凑，又比直接删掉更醒目，读者仍能看出「这里是分隔」
- **能不动就不动**：1~2 个空行、≤2 个空格、≤4 宽度的缩进都是正常排版语义，压掉反而让段落粘在一起、列表层级消失
- 分隔标号在 Word 中为居中、灰色（#808080）、略小字号；与「压缩冗余连续空行」同开时，剩下的 1~2 个空行会再被收紧为 1 个
- **已知取舍**：靠空格对齐的「伪表格」（`名称    数量    单价`）会被压成一格，失去列对齐——需要保留列宽时请关掉本开关或改用真实表格；同理，用空格手工排的签名/落款位置也会被压平

## 截图裁切排版

手机截长图、网页截屏、平板做题截图，往往带着顶部状态栏、底部导航条和一圈黑边，直接贴进 Word 又小又花。
「截图裁切排版」页把这件事做成一条流水线：**导入 → 自动识别四边 → 手动微调 → 按纸张导出**。

### 输入与排序

- 支持 PNG / JPG / WebP，可一次拖入多张，也可点「导入截图」选择
- 文件名里带 `20240512_182233` 这类时间戳时，自动按拍摄顺序排列；没有则按文件名排序
- 导入后仍可继续拖图追加；卡片右上角的 ◀ ▶ 可调整顺序，× 移除单张

### 自动识别（默认模式）

| 步骤 | 做法 |
| --- | --- |
| 粗定位 | 整图缩到 540px 宽，只统计中间 15%~85% 的列，算出逐行亮度曲线 |
| 上边界 | 从上往下找到第一条亮度 > `max(100, 2×阈值)` 的行，跳过状态栏与纯黑顶边 |
| 下边界 | 正文出现后，连续 20 行亮度低于阈值即判为页面结束（底部黑边/导航条） |
| 精修 | 回到原图，在粗定位 ±100px 内逐行复算，避免缩略图误差 |
| 避让蓝钮 | 在页面下 1/3 区域扫描偏蓝色行，命中即上移 15px，躲开截图工具/悬浮球 |
| 左右裁边（可选） | 在页面带内统计每列亮度与波动，剥掉两侧「又暗又均匀」的列；带纹理的深色列不会误裁，最多各裁 20% 宽度 |

可调项：**黑边阈值**（20~120，越大越容易把浅灰区域判成黑边）、**避让底部蓝钮**、**左右自动裁边**（默认关）、**纸张**、**页边距**（0~30mm）。

左右裁边默认关闭，普通手机/网页截图的结果与之前完全一致；只在带 letterbox 黑边的视频截图、平板录屏这类场景才需要打开。

### 手动微调

- 卡片上的红色 **TOP ↕ / BOT ↕** 手柄可上下拖动，**LEFT ↔ / RIGHT ↔** 可左右拖动，都只改当前这一张
- 手柄获得焦点后可用方向键微调（10px，按住 Shift 为 50px）；四块半透明遮罩实时标出保留区域
- 卡片底部显示保留尺寸（宽 × 高），改到满意直接导出
- **首图比例同步**：以第 1 张的四边裁切比例为准，等比套用到其余所有图（适合同一台设备连续截的图）
- **模板学习**：给一张原图和它对应的已裁好样本，程序反推样本在原图中的**左右上下四条边**，学到的比例再套到全部截图；适合自动识别总差几像素的固定场景

模板学习的具体做法：把原图缩到 360px 宽，样本按多组倍率（0.25×~5×）重采样后做行带匹配，只在纹理丰富的行取探针（纯白边、空白页脚不参与），纵向粗扫+精修、横向全扫+精修，最后用匹配残差换算置信度。因此：样本顶部是白边、样本被缩放导出过、左右也裁过，都能正确学出来；样本与原图对不上（置信度低于 55%）会明确拒绝，而不是把错误的裁切悄悄套到所有图上。

### 导出

| 形式 | 说明 |
| --- | --- |
| 单张 PNG | 只导出该卡片裁切后的图片 |
| 打包 ZIP | 全部裁切图按 `001_原名_cropped.png` 编号打包，中文文件名正常显示 |
| PDF | 每页一张图，以 150dpi 换算物理尺寸后在版心内等比居中；纸张可选 **A4（默认）/ A5 / A3 / Letter**，可设四边留白 |

右侧预览与导出用的是同一份排版算法（`layoutOnPage`），所见即所得；预览支持 75%~250% 缩放，点缩略图可定位到对应卡片。

PDF 与 ZIP 都是仓库内自研的极简编码器（`src/lib/pdf.ts`、`src/lib/zip.ts`），不依赖 jsPDF / JSZip 等 CDN 资源，因此断网、拷到 U 盘后依然可用。

### 边界

- 纯白背景、没有明显黑边的截图，阈值过高会把正文上方留白裁掉——调低阈值即可
- 深色模式截图（夜间阅读、暗色 App）：页面本身是暗的，与黑边同色，自动识别会失效，请改用模板学习或手动拖线
- 左右方向默认保留整幅；需要横向裁切时用 LEFT/RIGHT 手柄手动拖，或打开「左右自动裁边」（只认深色且均匀的列）
- 横向长图（宽 > 高）不适用
- 导出 PDF 是图片型页面，文字不可选中、不可搜索；需要可选中的文字请走「快速排版工作区」导出 .docx

## 使用

**双击 `文档压缩标准化工具.html` 即可。** 它是单文件：脚本、样式全部内联，不联网、不启动服务、不需要安装 Node，可以单独拷到 U 盘或桌面使用。

`一键启动.bat` 只是便利入口：文件在就直接打开，文件缺失时才调用 npm 构建一次。

详细操作与常见问题见 `使用说明.txt`；想快速验证全部功能，把 `示例文案.txt` 的内容复制进工具即可逐项对照。

## 开发

```bash
npm install
npm run dev        # 开发预览 http://localhost:5173
npm run build      # 构建，产出根目录的「文档压缩标准化工具.html」
npm run typecheck  # TypeScript 类型检查
```

构建脚本 `scripts/emit-single-file.mjs` 会把 vite 产物搬到项目根目录，并在搬运前校验「没有任何外链脚本 / 样式」，确保单文件拷走后仍能打开。

主要模块：

- `src/App.tsx` — 应用外壳：导航、主题、全局状态、导入/导出编排
- `src/constants.ts` — 内置模板、流水线步骤、开关文案、空白压缩阈值
- `src/types.ts` — 公共类型
- `src/components/` — 标签页组件（快速 / 批量 / 截图裁切）+ 轻量排版预览渲染器
- `src/components/settings/` — 系统设置式窗口：窗口外壳（分类导航 / 焦点陷阱）+ 排版标准 / 处理工作流 / 通用 / 关于四个分类
- `src/lib/mathAst.ts` — LaTeX 子集解析为 AST，供预览与 Word 共用
- `src/lib/omml.ts` — AST → docx 原生公式（OMML）
- `src/lib/chem.ts` — 化学式/离子识别与解析（含误判防护）
- `src/lib/richText.ts` — 公式/化学式定界符切分与分段模型
- `src/lib/textProcessing.ts` — 离线清洗主流程（按固定顺序串起各步骤）
- `src/lib/questionNumbering.ts` — 题目三级识别与符号化（序号字符集 + 递增序列 + 关键词）
- `src/lib/markdownTable.ts` — Markdown 表格识别（表头 / 对齐 / 行列切割）
- `src/lib/whitespace.ts` — 空白压缩与分隔标号替换（含阈值与保护区域）
- `src/lib/imageCrop.ts` — 截图四边识别、裁切与模板学习（多尺度行带匹配 + 置信度）
- `src/lib/pdf.ts` — 极简图片型 PDF 生成器（A4，JPEG 直嵌，无第三方库）
- `src/lib/zip.ts` — 极简 ZIP 打包（store 模式，UTF-8 文件名）
- `src/lib/fonts.ts` — 本机字体探测
- `src/lib/docx.ts` — 生成 .docx（原生公式 + 上下标 + 表格 + 层级样式）
- `scripts/emit-single-file.mjs` — 构建后处理：产出根目录单文件

## 命名规范

### 设计目标

1. **见名知义**：不打开文件就能判断用途与归属——按「半年后的自己 = 新成员」标准取名
2. **自然聚簇**：同类文件在资源管理器排序后相邻，职责相近的配对模块边界清晰、词根不重叠
3. **跨场景安全**：文件名在资源管理器、cmd/bat、Git、浏览器 `file://` 下都不需要引号或转义
4. **名随物定**：常用文件名保持稳定，不随版本、日期漂移，外部引用不会失效

### 适用范围

仓库内所有文件与目录，按六类管理；用户自己的文件不受此约束。

### 各类文件的命名格式

| 类别 | 范围 | 格式 | 本仓库示例 |
| --- | --- | --- | --- |
| A. 用户可见文件 | 交付物、双击入口、说明、示例语料 | **中文名词性短语**，无空格、无日期、无版本号；入口脚本允许动宾结构 | `文档压缩标准化工具.html`、`一键启动.bat`、`使用说明.txt`、`示例文案.txt` |
| B. React 组件 | `src/components/*.tsx` | **PascalCase**，名词，以职责后缀（`Tab`/`View`）结尾；文件名与导出名一致 | `QuickTab.tsx`、`FormattedText.tsx` |
| C. 逻辑库 | `src/lib/*.ts` | **camelCase 或全小写单词**，单数名词，描述「做什么」而非「在哪用」 | `mathAst.ts`、`chem.ts`、`whitespace.ts` |
| D. 工具脚本 | `scripts/*.mjs` | **kebab-case**，动词开头 | `emit-single-file.mjs` |
| E. 配置文件 | 根目录 | 跟随工具链约定（npm / tsc / vite 的默认名），不自造同义别名 | `package.json`、`tsconfig.json`、`vite.config.ts` |
| F. 备份 / 存档 | 项目目录之外 | `项目名-备份-YYYYMMDD`；同一天多份追加 `-HHmm` | `文档压缩标准化工具-备份-20261113` |

### 关键约定

- **日期**：只允许出现在 F 类（备份/存档）文件名末尾，统一 `YYYYMMDD`——字典序即时间序。禁止 `2026-11-13`、`11.13`、`1123` 等写法
- **版本号**：不进文件名。版本记录在 `package.json` 的 `version` 字段，交付物同名覆盖更新；文件名带 `v2` 必然催生 `final`、`final2`
- **配对模块**：职责相近的模块用**不同词根**区分——`docx.ts` 负责文档装配，`omml.ts` 负责公式 XML；避免 `docxMath` 这类前缀重叠、边界模糊的命名
- **大小写**：扩展名一律小写（`.txt` 而非 `.TXT`）；B 类文件名与默认导出名严格一致（`QuickTab.tsx` ↔ `QuickTab`）
- **分隔符**：中文文件名内部直接连写不加空格；代码文件用大小写分词（`questionNumbering.ts`），不用 `-` 或 `_`（D 类 kebab-case 脚本除外）

### 禁用字符与情形

| 禁止 | 原因 |
| --- | --- |
| 空格（半角与全角） | 命令行必须加引号，bat 脚本里的隐形炸弹 |
| `\ / : * ? " < > |` | Windows 文件系统保留字符 |
| `& ^ % !` | cmd 转义字符，bat 中会打断命令 |
| 文件名结尾的句点 | Windows 会静默吞掉 |
| 中文间隔号 `·`、破折号 `——` | GBK/UTF-8 双编码环境下易乱码（全角括号可用） |
